# Existing system comparison

## Selection and evidence basis
Five relevant system families cover hosted collaboration, self-hosted file collaboration, dedicated document management and a Kazakhstan-market enterprise offering: SharePoint with Power Automate, Nextcloud with Flow, Mayan EDMS, Paperless-ngx and Documentolog Platform/d8n.ai Enterprise. The same eight criteria apply to all. Documentation for the first four was checked on 19 October 2026; Kazakhstan sources were checked on 23 October 2026. This is a documentation review, not a hands-on benchmark, security audit or price quotation. In March 2026, the vendor reported that it had begun migrating Documentolog Platform clients to d8n.ai [S30]. The fifth column uses the current d8n.ai internal-document solution for feature claims and the Kazakhstan register for Platform identity; it does not assume identical configuration across generations. Documentolog Business and Doculite are separate offerings.

Legend: D means documented capability, C means configuration or an additional component is needed, and U means the exact behaviour was not verified in the inspected pages. U does not mean absent. Product configuration, edition and future versions can change results.

## Interpretation and build versus configure decision
The comparison shows substantial overlap with the proposed project. It does not justify claims that alternatives lack permissions, workflows or audit features. SharePoint provides an explicit example of version-aware approval. Mayan is a strong candidate for a configuration trial. Paperless focuses on ingestion and document organisation in the inspected workflow documentation, so equivalence to an author–reviewer lifecycle needs testing. Nextcloud's automatic version expiry requires checking against the desired record policy. The Documentolog/d8n.ai family is a direct local-market alternative with documented internal routing, versions and archive/search [S28, S29, S30]; exact frozen-version approval and the scope of audit-history evidence still need a hands-on check. Ten reported interviews took place in Astana ([interview analysis](02_relevance.md)); the pilot organisation and its procurement constraints are not established. This is a Kazakhstan-market comparison, not a measured fit assessment for any of those organisations.

Our provisional reason to build is educational engineering work around a narrow approval workflow with inspectable rules, a consistent user journey and an evaluation baseline. Commercial necessity is unproven. Use the interview-derived scenarios, including sequential approvals and recovery from a returned version, for a time-boxed configuration trial in an accessible alternative such as SharePoint, Mayan or the current d8n.ai offering. Record route setup effort, version binding, access isolation and recovery from requested changes. If configuration satisfies the mandatory requirements with acceptable administration, recommend adaptation or narrow the custom contribution with supervisor agreement.

The proposed prototype illustrates a design choice; it is not a sixth production competitor and has not met production security or storage requirements. No product price, compliance certification or unsupported absence claim forms part of the comparison.
